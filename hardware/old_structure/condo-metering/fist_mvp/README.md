# 🧪 First MVP — คอมตัวเอง + USR-TCP232-304 + slave 2 บัส

> พิสูจน์เส้นทางข้อมูลจริงก่อนลงทุน: **PC → switch → USR-TCP232-304 → RS485 → slave → ตอบกลับ**
> รายการซื้อ + ลิงก์อยู่ที่ [hardware.md](hardware.md)

## 1. ผังการต่อ

```
คอมตัวเอง (poller + pymodbus)
   │ LAN
   ▼
TP-LINK Switch 5 port
   ├───► USR-TCP232-304 #1  ── RS485 (A/B/G) ──┬── มิเตอร์ไฟ #1   addr 1
   │     "บัสไฟ"  192.168.0.201                 └── มิเตอร์ไฟ #2   addr 2
   │
   └───► USR-TCP232-304 #2  ── RS485 (A/B/G) ──── DIYMROE ESP32   addr 121
         "บัสน้ำ"  192.168.0.202                    ▲ DI1     ▲ DI2
                                                    │ พัลส์ NPN │
                                              flow sensor #1  flow sensor #2

ไฟเลี้ยง:  MDR-60-24 #1 → USR #1 + USR #2 (รับ 5–36V)
          MDR-60-24 #2 → DIYMROE (9–24V ✓) + flow sensor ×2 (5–24V ✓)
มิเตอร์ไฟ: เลี้ยงตัวเองจาก 220V ที่วัด
```

จำลองโครงสร้างจริงครบทุกชั้น: **IP เลือกบัส → Unit ID เลือกอุปกรณ์** เหมือนดีไซน์คอนโดเป๊ะ แค่ย่อส่วน

## 2. ตั้งค่า USR-TCP232-304 (ทำทีละตัว!)

> ⚠️ ค่าโรงงานทั้งสองตัวเป็น **IP เดียวกัน (192.168.0.7)** — ห้ามเสียบพร้อมกันก่อนตั้งค่า

ต่อทีละตัวเข้า switch แล้ว:

1. ตั้ง IP คอมชั่วคราวเป็น `192.168.0.100 / 255.255.255.0`
2. เปิดเบราว์เซอร์ → `http://192.168.0.7` → login `admin / admin`
3. หน้า **Serial Port**:
   - Baud Rate `9600` · Data `8` · Parity `None` · Stop `1`
   - **Work Mode = `TCP Server`** · Local Port = `502`
   - ✅ **เปิด "ModbusTCP" (Modbus TCP ⇄ RTU conversion)** ← หัวใจของทั้งงาน ถ้าลืมข้อนี้จะได้ transparent mode แล้วอ่านไม่รู้เรื่อง
4. หน้า **Local IP Config**: Static IP — ตัวที่ 1 = `192.168.0.201` · ตัวที่ 2 = `192.168.0.202`
5. Save → Restart → แปะสติกเกอร์ IP ที่ตัวกล่อง

## 3. การเดินสาย

### บัสไฟ (USR #1)

| จาก | ไป | สาย |
|-----|-----|-----|
| USR #1 ขั้ว `485+ (A)` | มิเตอร์ #1 `A` → มิเตอร์ #2 `A` (daisy) | เหลือง |
| USR #1 ขั้ว `485- (B)` | มิเตอร์ #1 `B` → มิเตอร์ #2 `B` | เขียว |
| USR #1 `GND` | — (มิเตอร์มักมีแค่ A/B — ภาค RS485 isolated ในตัว) | — |

- ไฟเข้ามิเตอร์: **220V ผ่าน MCB** — ⚠️ ระวังสูงสุด งานนี้แตะไฟบ้าน ปิดเบรกเกอร์ก่อนแตะทุกครั้ง
- ตั้ง addr มิเตอร์: ตัวที่ 1 = `1` (มักเป็นค่าโรงงาน), ตัวที่ 2 = `2` (ตั้งผ่านปุ่มหน้าเครื่องหรือเขียน register — ดูคู่มือที่มากับตัวจริง) **ตั้งทีละตัวตอนอยู่บนบัสคนเดียว**

### บัสน้ำ (USR #2)

| จาก | ไป | สาย |
|-----|-----|-----|
| USR #2 `A` / `B` / `GND` | DIYMROE `A` / `B` / `GND` | เหลือง/เขียว/เทา — **ตัวนี้ต้องต่อ GND ด้วย** (บอร์ด ESP32 ไม่ isolated) |
| flow #1 สาย เหลือง (SIG) | DIYMROE opto input `DI1` | |
| flow #2 สาย เหลือง (SIG) | DIYMROE `DI2` | |
| flow แดง/ดำ | MDR-60-24 #2 `+V` / `-V` | GND ร่วมกับบอร์ด |

- DIYMROE รับ 9–24V → ใช้ 24V จาก MDR ได้ตรง ๆ
- 🔴 **งานเฟิร์มแวร์ (ชิ้นเดียวของ MVP):** แฟลช ESP32 ให้ (1) นับพัลส์ DI1/DI2 + debounce (2) เซฟ NVS ทุก 100 พัลส์/60 วิ (3) เป็น Modbus RTU slave addr `121` — ตอบ FC03 reg `0x0000-0x0001` = พัลส์สะสม CH1 (uint32), `0x0002-0x0003` = CH2


## 5. เช็คลิสต์ (เรียงตามลำดับ ทำข้ามไม่ได้)

- [ ] ตั้งค่า USR ทั้งสองตัวเสร็จ → `ping 192.168.0.201` และ `.202` ติด
- [ ] ต่อมิเตอร์ #1 ตัวเดียว → `python poll_test.py` อ่าน V/A/W/kWh ได้ → **เทียบกับตัวเลขบนจอมิเตอร์** ต้องตรง
- [ ] ⚠️ ถ้าอ่านได้แต่ค่าประหลาด (เช่น kWh หลักล้าน) = **register map/byte order ไม่ตรง** — มิเตอร์ในลิงก์ไม่ระบุยี่ห้อชัด อย่าเดา ให้เทียบกับคู่มือในกล่อง แล้วแก้ `PROFILE` ในสคริปต์
- [ ] ต่อมิเตอร์ #2 เพิ่ม (addr 2) → อ่านได้ทั้งคู่
- [ ] แฟลช DIYMROE → อ่าน addr 121 ผ่าน USR #2 ได้ (ค่าเริ่ม 0)
- [ ] เป่าลม/เทน้ำผ่าน flow sensor → ค่านับขยับ → ตวงน้ำ 1 ลิตรเทียบจำนวนพัลส์ (= K-factor)
- [ ] ถอดปลั๊ก DIYMROE แล้วเสียบใหม่ → **ค่านับต้องไม่หาย** (พิสูจน์ NVS)
- [ ] ดึงสาย LAN ระหว่าง poll → สคริปต์ต้อง timeout แล้วไปต่อ ไม่ค้าง
- [ ] รันทิ้งไว้ข้ามคืน `--loop 30` → เช้ามาดู error rate

## 6. จาก MVP → ระบบจริง

| MVP | ระบบจริง | เปลี่ยนอะไร |
|-----|----------|-------------|
| คอมตัวเอง | Mini PC 4×LAN | ย้ายสคริปต์ไปรัน ไม่แก้โค้ด |
| switch 1 ตัว รวมทุกอย่าง | switch ไฟ + switch น้ำ แยก | เปลี่ยนแค่ IP ใน config |
| USR ×2 (บัสละตัว) | gateway ประจำชั้น | เพิ่ม IP ใน config ต่อชั้น |
| poll แล้ว print | poll แล้ว publish MQTT → VPS | ต่อยอด poller ตัวเดิม |
